# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [1.3.0] - 2026-08-04

### Added

- **App-in-use detection**: before each upgrade, the app's running
  processes (resolved via the uninstall registry and a process scan)
  trigger a yes/no prompt to close them — a graceful window close first,
  force-kill only for what survives. Declining upgrades anyway.
- Custom modal confirmation dialog that the app can also dismiss itself,
  so an unanswered prompt can never leave the window disabled.

### Safety rules for closing processes

- Never closes this app or any of its ancestors, so upgrading the
  terminal or launcher that started it cannot kill it mid-batch.
- Rejects shared install roots (Windows, Program Files itself, Common
  Files, the user profile, AppData) that would otherwise match unrelated
  or system processes.
- Requires a package name to match a registry entry exactly or with only
  a version/qualifier suffix, so "Microsoft Edge" never matches
  "Microsoft Edge WebView2 Runtime".
- Re-checks that a PID still runs the executable that was detected before
  killing it, so a recycled PID is never hit; force-kill does not cascade
  to child processes that may belong to other applications.

### Fixed

- Map winget codes 0x8A150001/0x8A150006/0x8A150008 to readable reasons;
  generic installer failures keep the installer's exit code and log path
  in the message.
- A failing preflight or upgrade batch can no longer kill the worker
  thread and leave the UI stuck in its busy state.
- Cancel is honoured after the preflight, so a cancelled batch no longer
  starts one more install.
- The package banner now prints before preflight output, keeping console
  lines in the right section.

## [1.2.0] - 2026-08-04

### Added

- **Failure reasons**: failed upgrades now show *why* (app running, needs
  admin, disk full, pinned, no network, …), mapped from winget's documented
  return codes and shown on the package card, status bar, and console.
- Per-package selection checkboxes with **Upgrade Selected** and a
  *Select all* toggle; deselected packages are remembered across scans.
- **Cancel** button for batch upgrades (the in-flight package finishes
  cleanly, the rest are skipped).
- Dark / Light / System theme switcher, persisted in
  `%LOCALAPPDATA%\WingetUpgradeManager\config.json`.
- Loading, empty, and error states in the package list — a failed scan no
  longer looks like "all up to date".
- Pinned packages are now shown (deselected by default) instead of hidden.
- Reboot-required results are reported distinctly from failures.
- Application icon, embedded Windows version metadata, and a version number
  in the title bar.
- Rotating log file at `%LOCALAPPDATA%\WingetUpgradeManager\app.log`.
- Test suite for output parsing and return-code mapping; CI workflow with
  lint, tests, and a build smoke test; Dependabot config.
- Community docs: contribution guidelines, code of conduct, and issue/PR
  templates (committed after v1.1.0 was tagged).

### Fixed

- **Localized Windows support**: winget output is now parsed structurally
  instead of matching English header words, which previously made the app
  report "all up to date" on non-English systems.
- Wide (CJK) characters in package names no longer corrupt column parsing.
- Localized summary lines are no longer parsed as phantom packages.
- Upgrade success is now determined from winget exit codes instead of
  grepping for English output text; "no applicable update" and
  "reboot required" are no longer counted as failures.
- The update scan can no longer hang forever on a source-agreement prompt
  (non-interactive flags, stdin detached, 180 s timeout).
- After a batch upgrade, failed packages are no longer shown as "✓ Done".
- The overall progress bar no longer reaches 100 % when the last package
  *starts*.
- Refresh, single upgrades, and batch upgrades can no longer run
  concurrently and destroy each other's UI state.
- Closing the window during an upgrade now asks for confirmation.
- Crash on Python 3.8 at import time (PEP 585 generics) fixed via
  `from __future__ import annotations`.

### Changed

- Release builds go through `build.py` in CI, with a tag-vs-version check;
  dependencies are pinned for reproducible builds.
- README/SECURITY claims corrected (checksums are generated by the release
  workflow, not by GitHub; builds are attested rather than reproducible).

## [1.1.0] - 2026-01-27

- Release workflow: updated action versions, SHA256 checksum generation, and
  build provenance attestation.

## [1.0.0] - 2026-01-27

Initial release: package list, one-click upgrades, live console, dark theme.
